# Dammie AI Web

The web workspace is the Next.js 15 frontend for Dammie AI. It has two jobs:

1. Render small Telegram Mini App screens for customer actions that need a
   signed Telegram identity, such as signup, managing saved bank accounts, and
   approving a swap or NGN withdrawal.
2. Render the administrator operations console for reviewing users,
   transactions, balances, conversations, catalog configuration, and platform
   fees.

The Telegram bot remains the primary customer interface. The web app does not
implement the chat agent; it presents the trusted action links generated by the
API and submits the resulting forms.

## Technology

- Next.js `15.3.5` App Router.
- React `19` and TypeScript.
- TanStack Query for client-side query/mutation state.
- Axios for customer Mini App requests.
- `@twa-dev/sdk` for Telegram Web App `initData` and Mini App controls.
- Tailwind CSS v4, Radix UI primitives, Lucide icons, and Sonner toasts.

## Routes

| Route | Surface | Behavior |
| --- | --- | --- |
| `/` | Public landing page | Hero, technology overview, and footer |
| `/auth/:slug` | Telegram Mini App | Complete signup with personal details, BVN, and four-digit transaction PIN |
| `/bank/:slug` | Telegram Mini App | Select a bank and submit an account number for provider verification |
| `/banks/:slug` | Telegram Mini App | List and remove saved bank accounts |
| `/transaction/:slug` | Telegram Mini App | Enter the transaction PIN to approve a pending swap |
| `/withdrawal/:slug` | Telegram Mini App | Review a withdrawal, choose a saved bank account, and approve with PIN |
| `/admin/login` | Admin | Sign in with administrator credentials |
| `/admin` | Admin | Operational overview and recent activity |
| `/admin/users` | Admin | Search and filter customer accounts |
| `/admin/users/:userId` | Admin | Inspect wallets, transactions, account versions, and conversations |
| `/admin/catalog` | Admin | Manage currencies, networks, and currency/network relationships |
| `/admin/fees` | Admin | Manage swap/withdrawal fee rules and inspect fee audit history |

The `:slug` values come from Telegram action links. For customer mutations,
the backend uses the signed Telegram identity as the source of truth. In
particular, the legacy bank-account path may contain a user ID, but the API
deliberately ignores it.

## Customer request flow

Customer calls are defined in `endpoints/api.ts` and use the Axios instance in
`config/api.ts`:

```text
Telegram Web App SDK
        |
        | WebApp.initData -> X-Telegram-Init-Data on requests
        v
Axios client -> configured API base URL -> Express API
        |
        v
React Query mutation -> toast -> close Mini App on success
```

The Axios request interceptor:

- Uses `NEXT_PUBLIC_API_URL` as its base URL.
- Adds the raw `WebApp.initData` value to
  `X-Telegram-Init-Data` when the app is running in Telegram.
- Sends JSON content types for normal form submissions.
- Uses a ten-second request timeout.

The API validates the Telegram HMAC, timestamp, user, and replay policy. A
browser opened outside Telegram does not have valid `initData`, so customer
mutations are expected to fail authentication.

Customer endpoints currently called by the web app are:

```text
POST users/create_user/:slug
POST users/add_bank_account/:slug
GET  users/bank_accounts
DELETE users/bank_accounts/:bankId
POST users/approve_transaction/:slug
GET  users/withdrawals/:slug
POST users/approve_withdrawal/:slug
```

The withdrawal review is read-only and can be fetched before the approval
mutation. It returns the amount, fee, total, status, current balance, and
masked saved bank accounts. The approval submits only the selected bank ID and
PIN; the API re-checks ownership and state.

On successful customer mutations, the form displays a Sonner toast and calls
`WebApp.close()` through `useTelegramWebApp`. API errors are converted to a
user-facing message by `lib/utils.ts`.

## Admin request flow

Admin calls use `lib/admin-api.ts`, not the customer Axios client. The helper
uses the same `NEXT_PUBLIC_API_URL` base as customer calls, appends `/admin`,
and includes credentials so the HTTP-only admin cookie is sent with requests.

The admin session boundary calls `/auth/me` before rendering protected routes.
An unauthenticated response redirects to `/admin/login`; a successful login
stores the returned admin identity in the React Query cache and navigates to
`/admin`.

Admin pages use TanStack Query for reads and mutations. User, transaction,
account-version, and conversation views use opaque cursor pagination. Catalog
and fee mutations refresh the relevant query after success. The API also
requires an allowed `Origin` for admin mutations.

## Environment and API proxy

Copy the example file before starting the workspace:

```bash
cp .env.example .env
```

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | Yes in production | Browser-side API base URL, including `/api/v1` |

Recommended local values:

```dotenv
NEXT_PUBLIC_API_URL=http://127.0.0.1:3001/api/v1
```

When deploying the API separately, set `NEXT_PUBLIC_API_URL` to its reachable
origin with the `/api/v1` prefix, and configure the API `FRONTEND_URL` and
`ADMIN_FRONTEND_URL` to the web origin.

## Local development

From the repository root:

```bash
bun install
bun --filter @dammie/web dev
```

Or from this directory:

```bash
bun run dev
```

Open <http://localhost:3000>. Customer Mini App routes need to be opened from
Telegram with valid action links; opening them directly in a normal browser
will not provide signed Telegram auth data.

## Commands

```bash
bun run dev
bun run build
bun run start
bun run lint
bun run typecheck
```

`bun run start` serves the production build and requires `bun run build` first.
The web workspace currently has no standalone test script; root-level checks
run the test scripts provided by each workspace.

## UI organization

```text
app/
  page.tsx                         public landing page
  auth/[slug]/page.tsx             signup Mini App
  bank/[slug]/page.tsx             bank-account Mini App
  transaction/[slug]/page.tsx      swap approval Mini App
  withdrawal/[slug]/page.tsx       withdrawal approval Mini App
  admin/                            protected operations console
components/
  complete-signup-form.tsx          customer signup form
  add-bank-account-form.tsx         bank verification form
  approve-transaction-form.tsx      swap PIN form
  approve-withdrawal-form.tsx       withdrawal review/approval form
  admin/                            admin shell, tables, dashboards, and pages
  ui/                               reusable Radix/Tailwind UI primitives
config/api.ts                       customer Axios client
endpoints/api.ts                    customer endpoint functions
lib/admin-api.ts                    admin fetch client and response types
```

`app/provider.tsx` creates the shared TanStack Query client and global Sonner
toaster. `app/layout.tsx` supplies the application metadata, Geist fonts, and
providers. The admin layout adds the session boundary and admin theme.

## Production checklist

- Set `NEXT_PUBLIC_API_URL` to the real API origin plus `/api/v1`; do not leave
  the local development value in a separately hosted deployment.
- Ensure the API allows the web origin through `FRONTEND_URL` and
  `ADMIN_FRONTEND_URL`.
- Serve the web and API over HTTPS so Telegram Mini App links and secure admin
  cookies work correctly.
- Run the API migrations and start PostgreSQL, Redis, Telegram, and provider
  integrations before testing customer actions.
- Open customer action routes from Telegram, not as unauthenticated public
  forms.
